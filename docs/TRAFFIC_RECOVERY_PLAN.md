# ITVedas Traffic Recovery Plan

## Objective
Recover organic search traffic by improving page quality, crawl efficiency, topical authority, and utility value rather than increasing page count.

## Operating principles

1. People-first content is the primary ranking strategy.
2. Automated news volume stays constrained until indexing health improves.
3. Every new page must have a clear user intent and unique value.
4. Tools are a core acquisition channel and should solve real IT problems.
5. Internal links should connect tools, guides, security data, and services.
6. Low-value, thin, duplicate, and obsolete pages should be consolidated, redirected, or excluded from search.

## Phase 1 — Stabilize search inventory

- Keep news publishing at a maximum of one curated batch per day.
- Require the news quality gate before publication and sitemap inclusion.
- Keep thin/near-duplicate pages out of the sitemap and eligible search index.
- Audit existing news clusters and consolidate overlapping stories.
- Keep CVE pages useful as reference/data pages; avoid generating repetitive prose around every update.

## Phase 2 — Build the ITVedas utility moat

Prioritize tools with clear search intent:

- IP address and subnet calculators
- DNS lookup and propagation tools
- WHOIS/RDAP lookup
- SSL/TLS certificate checker
- HTTP header checker
- JWT decoder/inspector
- Base64 encoder/decoder
- URL encoder/decoder
- JSON formatter/validator
- Regex tester
- Cron expression generator
- CIDR calculator
- MAC/vendor lookup
- Port/reference tools
- PowerShell and Windows troubleshooting utilities
- Cloud and DevOps utilities
- Security header and email-authentication checkers

Each tool should have a unique landing page with: what it does, when to use it, example inputs, explanation of results, related tools, related guides, FAQ, and structured metadata where appropriate.

## Phase 3 — Topic clusters

Build authoritative clusters around:

- Networking
- Cybersecurity
- Windows / PowerShell
- Linux
- Cloud / DevOps
- IT administration
- AI for IT

Prefer one strong canonical guide plus supporting task-specific pages over many near-identical articles.

## Phase 4 — Internal linking

Every important tool should link to relevant guides and every guide should link to useful tools. Add contextual links from CVE/security pages to affected technology guides and diagnostic tools.

## Phase 5 — Content automation policy

AI may research, outline, draft, classify, summarize structured data, and assist editing. It must not be used as a reason to publish large numbers of commodity pages. Generated content should pass factual, duplication, usefulness, and technical validation before publication.

## Phase 6 — Measurement

Track weekly:

- indexed pages
- discovered/crawled but not indexed pages
- organic clicks
- impressions
- CTR
- average position
- top landing pages
- tool usage
- news share of sitemap
- pages with zero organic impressions

Traffic recovery is successful when indexed quality pages and clicks trend upward while discovered-not-indexed and low-value inventory trend downward.
