# ITVedas Traffic Recovery Baseline

## Purpose

This document records the traffic-recovery priorities identified from the repository audit and live Search Console evidence. It is a planning baseline, not a claim that every URL should be indexed.

## Current priorities

1. Make important tools and AI-tool hubs crawlable through normal internal links.
2. Keep the sitemap limited to canonical, indexable URLs.
3. Prevent automated news volume from expanding during recovery.
4. Prefer consolidation and improvement of existing content over bulk publishing.
5. Replace internal `.html` links with clean URLs over time to avoid redirect hops.
6. Measure indexing and search performance before increasing content volume.

## Recovery principle

ITVedas should optimize for useful pages that satisfy a distinct search intent, not for the number of URLs published.

## Tool growth

New tools should be added only after the existing tool inventory has strong navigation, canonical URLs, sitemap coverage, useful supporting copy, and internal links to related guides.

## Measurement

Track weekly:

- Search Console clicks and impressions
- indexed pages
- sitemap-discovered pages
- pages with impressions
- pages with zero impressions
- news URL count
- tool URL count
- AI-tool URL count
- crawl/indexing anomalies

## Guardrails

- Do not mass-delete historical news URLs during the first recovery stage.
- Do not request indexing for every URL simply because it exists.
- Do not resume high-frequency automated news publishing until indexing quality improves.
- Do not create large batches of thin AI-generated pages.
