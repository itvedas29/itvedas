High Cannot connect to the internet — all pings fail
Problem
No internet access. ping 8.8.8.8 times out. Browser shows "No internet connection".
Diagnosis
ip addr show # check if interface has IP ip route show # check default gateway exists ping 192.168.1.1 # ping gateway — if fails, local issue ping 8.8.8.8 # if gateway ok, DNS/ISP issue cat /etc/resolv.conf # check DNS servers
Solution — Step by Step
  1. Restart network interface: sudo ip link set eth0 down && sudo ip link set eth0 up
  2. Request new IP via DHCP: sudo dhclient -r && sudo dhclient eth0
  3. Add Google DNS if resolv.conf is empty: echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf
  4. Add missing default route: sudo ip route add default via 192.168.1.1
  5. If still failing, restart networking service: sudo systemctl restart NetworkManager

Medium Common HTTP error codes and what actually causes them
Problem
A site or API returns an HTTP error code — 404, 500, 502 — and it's not obvious whether the problem is on the client side, your app, or the infrastructure in between.
Diagnosis
curl -I https://example.com/path # check status code + headers curl -v https://example.com/path # full request/response detail tail -f /var/log/nginx/error.log # reverse proxy errors tail -f /var/log/nginx/access.log # confirm the request even reached nginx
Solution — What Each Code Actually Means
  1. 400 Bad Request — malformed request syntax: bad JSON, oversized headers, or an invalid query string. Fix the client's request, not the server.
  2. 401 Unauthorized — the request has no valid authentication credentials. Check the auth token/header is actually being sent.
  3. 403 Forbidden — credentials are valid but the caller isn't permitted. Check ACLs, file permissions, or a WAF/security-group rule blocking the request.
  4. 404 Not Found — the resource genuinely doesn't exist at that path, or a routing rule/rewrite is misconfigured. Confirm the route exists server-side before assuming it's a typo.
  5. 429 Too Many Requests — a rate limit was hit. Check the Retry-After header and back off.
  6. 500 Internal Server Error — an unhandled exception in your application code. This is a server bug — check the app's own error log, not the proxy's.
  7. 502 Bad Gateway — the reverse proxy (nginx, an ALB) couldn't get a valid response from the upstream app. The app process crashed, isn't listening on the expected port, or returned garbage.
  8. 503 Service Unavailable — the server is overloaded or intentionally in maintenance mode, or a load balancer has no healthy backend targets.
  9. 504 Gateway Timeout — the upstream took too long to respond and the proxy gave up. Usually a slow query or an app stuck waiting on a dependency.

Medium Emails going to spam or not arriving at all
Problem
Your sending service reports the email as delivered, but recipients never see it — or it lands straight in spam.
Diagnosis
dig TXT yourdomain.com # look for SPF record dig TXT selector._domainkey.yourdomain.com # DKIM (selector from your provider) dig TXT _dmarc.yourdomain.com # DMARC policy
Solution — Step by Step
  1. Confirm an SPF record exists and includes your sending service: v=spf1 include:_spf.yoursendingservice.com ~all
  2. Confirm DKIM signing is active — your email provider gives you a DKIM selector TXT record to publish; unsigned mail is a strong spam signal on its own.
  3. Publish a DMARC record so receiving servers know what to do with mail that fails SPF/DKIM: v=DMARC1; p=quarantine; rua=mailto:dmarc@yourdomain.com
  4. Check your sending domain/IP against blocklists (MXToolbox, Spamhaus) — a prior sender on a shared IP can poison your reputation.
  5. Warm up new sending domains gradually — a sudden burst of volume from a brand-new domain reads as spam behavior to receiving servers.
  6. Review content: excessive links, ALL-CAPS subject lines, and a missing unsubscribe link all raise spam scores independent of your DNS setup.

High Disk 100% full — server unresponsive
Problem
df -h shows 100% usage. Applications crash, logs stop writing, server may become unreachable.
Find the culprit
df -h # which partition is full du -sh /* 2>/dev/null | sort -rh | head -10 # top directories by size du -sh /var/log/* | sort -rh | head -10 # often logs are the issue find / -name "*.log" -size +100M 2>/dev/null # big log files
Solution
  1. Clear old logs: sudo journalctl --vacuum-size=100M
  2. Remove old kernels: sudo apt autoremove --purge
  3. Clean apt cache: sudo apt clean
  4. Find and delete large temp files: sudo find /tmp -size +50M -delete
  5. Truncate large log file (safe): sudo truncate -s 0 /var/log/syslog
  6. Set log rotation: configure /etc/logrotate.conf

Everyday & Desktop Problems

7 problems
Medium Why does my WiFi keep disconnecting?
Problem
WiFi drops every few minutes and reconnects on its own, or requires manually rejoining the network — while other devices on the same network stay connected fine.
Diagnosis
The most common cause on laptops is Windows aggressively power-managing the WiFi adapter to save battery, which turns the radio off under light load. The next most common causes are outdated drivers and channel congestion from neighboring networks.
Solution — Step by Step
  1. Open Device Manager → Network adapters → your WiFi adapter → Properties → Power Management, and uncheck "Allow the computer to turn off this device to save power".
  2. Update the WiFi driver from the laptop or chipset manufacturer's site (Windows Update often ships an outdated generic driver).
  3. Forget the network and reconnect, re-entering the password — a corrupted saved profile is a common, easy-to-miss cause.
  4. On the router, switch to a less congested channel or move the device to the 5GHz band if available — 2.4GHz is crowded in dense apartment buildings.
  5. If the router has "band steering" or seamless roaming between access points, try disabling it — some client adapters handle the handoff badly and drop the connection instead.
wifinetworkingdriverswindows
Medium VPN client won't connect or times out
Problem
The VPN client sits on "Connecting…" indefinitely, or fails with a timeout or handshake error, even though the internet works fine without it.
Diagnosis
Confirm the base internet connection works with the VPN off. If it does, the most likely culprits are a firewall blocking the VPN's port/protocol, a network (hotel or public WiFi) that blocks VPN traffic outright, or — less obviously — an incorrect system clock breaking certificate validation.
Solution — Step by Step
  1. Check firewall/antivirus isn't blocking the VPN app or its ports: OpenVPN typically uses UDP 1194, WireGuard UDP 51820, IPsec UDP 500/4500.
  2. Switch protocol if your client allows it — OpenVPN over TCP port 443 gets through far more restrictive firewalls than UDP does, since it looks like ordinary HTTPS traffic.
  3. On Windows, reinstall the VPN client's virtual adapter (TAP/WireGuard adapter) if it's missing from ncpa.cpl — a botched update can leave it uninstalled.
  4. Verify the system clock is correct — certificate-based VPNs fail silently when the local time is wrong enough to invalidate the cert.
  5. If you're on public/hotel WiFi, try mobile data — some public networks block VPN protocols entirely regardless of client configuration.

High Troubleshooting a Windows Blue Screen of Death (BSOD)
Problem
Windows crashes to a blue screen showing a stop code (e.g. IRQL_NOT_LESS_OR_EQUAL, MEMORY_MANAGEMENT), either once or repeatedly.
Diagnosis
The stop code and any named .sys driver file on the blue screen are your two biggest clues. The usual causes, in order of likelihood, are a faulty or incompatible driver, bad RAM, overheating, and corrupted system files.
Solution — Step by Step
  1. Note the exact stop code and any driver file named on screen, or find it after the fact in Event Viewer → Windows Logs → System, filtered to "Critical" around the crash time.
  2. Run Windows Memory Diagnostic (mdsched.exe) or, for a more thorough pass, boot Memtest86 — bad RAM is one of the most common root causes of intermittent, hard-to-reproduce BSODs.
  3. If a specific driver was named, update it from the manufacturer's site, or roll it back in Device Manager if the crashes started right after an update.
  4. Repair system files: sfc /scannow, followed by DISM /Online /Cleanup-Image /RestoreHealth if SFC reports errors it can't fix.
  5. Check temperatures under load with a monitoring tool (HWMonitor or similar) — thermal instability can present as random BSODs that look driver-related but aren't.

Problem

Diagnosis
Most stuck-queue issues are the Print Spooler service holding a corrupted job, not the printer itself. "Offline" status is usually either a stale network address or the printer explicitly set to work offline.

High Computer won't turn on — no display, no POST
Problem
Pressing the power button spins the fans (or does nothing at all), but there's no manufacturer logo, no BIOS screen, and no completed POST beep sequence.
Diagnosis
This is a POST (Power-On Self-Test) failure, which means the hardware hasn't gotten far enough to hand off to the OS. The job is to isolate which component — RAM, GPU, PSU, or motherboard — is preventing POST, one at a time.
Solution — Step by Step
  1. Count any beep codes and check them against the motherboard's BIOS vendor (AMI, Award, and Phoenix all use different patterns) — this alone often points straight at the failing component.
  2. Reseat RAM sticks one at a time in slot 1 — loose or failed RAM is the single most common cause of no-POST.
  3. Reseat the GPU, or use the motherboard's onboard video output if it has one, to rule the GPU in or out.
  4. Check power: confirm both the 24-pin and CPU 4/8-pin connectors are fully seated — the CPU power connector is the most commonly missed cable during a build.
  5. Clear CMOS (remove the battery for 30 seconds, or use the reset jumper) — a corrupted BIOS setting can block boot entirely and this resets it to defaults.
  6. Strip to the bare minimum — CPU, one RAM stick, PSU, no GPU or drives — and add components back one at a time once it POSTs.

Low Decoding common Windows error codes (0x80070005 and friends)
Problem
Windows shows a cryptic hex error code during an update, install, or file operation, with no explanation of what it actually means.
Diagnosis
Most of these codes cluster into a handful of recurring causes: permissions, a corrupted update cache, or a critical system process crash. The code itself narrows it down fast once you know the common ones.
Solution — What Each Code Usually Means
  1. 0x80070005 — Access Denied. A permissions or ownership issue; try running as administrator or check the file/folder's ACLs.
  2. 0x8007000E — Out of memory/insufficient resources, frequently a corrupted Windows Update cache rather than an actual RAM shortage. Clear the SoftwareDistribution folder and retry.
  3. 0x800F0922 — Update failed to install; commonly a full System Reserved partition or a .NET Framework version conflict.
  4. 0x80072EE7 / 0x80072EFD — Network error reaching the Windows Update servers; check firewall/proxy settings before assuming it's a Microsoft-side outage.
  5. 0xc000021a — A critical system process terminated, usually right after a bad driver install or a failed update; often needs a boot into Safe Mode to roll back the change.
  6. For any code not listed here: run the built-in Windows Update Troubleshooter, then sfc /scannow and DISM /Online /Cleanup-Image /RestoreHealth — these two commands resolve the majority of unlisted codes.
